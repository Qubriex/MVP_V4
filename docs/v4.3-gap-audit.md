# v4.3 core logic vs the build — gap audit

Audit of the Core IP Dossier (baseline v4.3 + errata v4.3.1, 28 Sep 2026)
against the backend on `claude/learner-side-updates-vthycg`, after Phase 0
step 1 (Foundation). Every section of Part D is listed.

**Update (30 Sep 2026):** the items listed in section 3 are now built, with
frontend screens. They are marked **Built** in the tables below, along with
the parts of G, E, Rt and Rn they needed. V1 is fixed. PIN delayed unlock
(D-019) is built.

**Legend**
- **Built** — implemented and tested.
- **Partial** — some of it exists (often as pre-v4.3 MVP code) but not to the v4.3 rule.
- **Violates** — existing MVP code that contradicts a v4.3 rule. Each one is either fixed in this audit or tied to the step that replaces it.
- **Planned** — not built; the build-order step that delivers it is named.
- **Not code** — legal, contractual or process items. They are listed so nothing is lost.

Build steps: F = Foundation (done) · G = Capability Graph · R = Retrieval layer ·
T = Teaching loop · E = Evidence engine · Rt = Retention · Rn = Return ·
Rd = Readiness · D1 = Day-One · C = Consent and minors · Q = Quality ·
P1 = Phase 1 employer beta · P2 = Phase 2 learn back · P3 = Phase 3.

## 1. Summary

1. **Everything in the Foundation step is built.**
   - DAL and migrations.
   - Transactional outbox and worker.
   - Parameters loading from secure-config, over the priors.
   - Structured logger and rate limits.
   - Auth for all four actor types.
   - Tenancy scoping.
   - Both structural walls and the other structural tests.
2. **Most of the core logic (§02A, §3–§15, §18) is not built yet, by design.** It belongs to later steps. Nothing in those steps was dropped.
3. **Running MVP code broke six v4.3 rules.** Four are fixed now. The other two need whole later steps:

   | # | Rule | What the MVP did | Status |
   |---|---|---|---|
   | V1 | §7 "The teaching model … never writes the check it will be judged by" | `teachBrain` returned `checkQuestion` and the route stored it as the check. The import-wall test passed, but the behaviour broke the rule. | **Fixed.** `core/evidence/checkWriter.js` writes every check from the `gen:<node>` family with an HMAC seed. TEACH output never carries a question. Reviewed families with mutation validation are still to come (E). |
   | V2 | §7.3 "Raw model-scored answers are never reused as examples"; §2A "cross-learner knowledge never enters a prompt as another learner's words" | EVAL few-shots came from `eval_example_responses`, which every evaluation wrote back to (other learners' answers, labelled by the model). | **Fixed.** EVAL is zero-shot until the gold set exists, and nothing is written back. Tested. |
   | V3 | §6 and §17.3: no behaviour fingerprint for minors (unknown age = minor) | Fingerprint was stored for every learner. | **Fixed.** Stored for confirmed adults only. Tested. |
   | V4 | §2A.2 "scores … are never shown in the learner interface" | The check responses returned `score`. | **Fixed.** Removed; the UI never read it. |
   | V5 | §7.7 simulation-ready = every node passed, mean A ≥ 0.75, no unresolved failed review | The rule required average confidence ≥ 0.60. | **Fixed.** Now follows §7.7; the failed-review part activates with Rt. |
   | V6 | §5.5 / §2A R7: the CKB is chosen by transfer-rewarded Thompson sampling, not an effectiveness ranking | `culturalStore` still ranks by an EWMA `effectiveness_score`. | **Open → T** (CULT assignment, uplift, leakage). |

4. **Parts of Foundation differed from the dossier. Fixed now:**
   - Employer roles: `owner/recruiter/viewer` (§14.1), via migration 0003.
   - KYB rule: search is allowed before approval; requesting access is not (§14.1).
   - AI-call rate limits per account and per institution (§22).
   - The Appendix A constants missing from the priors were added.
   - The A.1 calibration register is now in `config/priors.js` and in the admin quality report.
5. **Learner PIN unlock:** resolved. Delayed unlock after 30 minutes, plus staff reset (D-019).
